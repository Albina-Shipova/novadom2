# Анализ скорости Нова Дом

Дата: 11 ноября 2026. Проверена главная страница https://novadom.asama.site/ и текущие локальные исходники. Изменения в сайт не вносились.

## Что измерено

Публичный сервер: GET главной с gzip — TTFB 87 мс, полная передача HTML 92 мс, 17 785 байт. Отдельные запросы CSS/JS: TTFB 77/90 мс. Это единичные запросы из среды проверки, не статистика реальных посетителей.

Браузер: Chromium, локальная копия по HTTP, холодные отдельные контексты, без прокрутки; Google Fonts намеренно отключены. Desktop 1440×900. Mobile 390×844, CPU ×4, сеть 200 000 байт/с, задержка 150 мс. По одному прогону, наблюдение 6 секунд после load. Сервер локальный, без gzip. Эти числа не являются результатом Lighthouse или измерением production Core Web Vitals.

## Приоритеты

1. Включить gzip/Brotli для text/css, application/javascript и image/svg+xml на сервере. GET с Accept-Encoding подтвердил отсутствие Content-Encoding для CSS и JS. Локальный gzip сокращает CSS со 136 141 до 25 188 байт, JS с 50 285 до 12 313 байт: суммарная экономия около 149 КБ, или 80%. HTML уже сжимается.
2. Пересмотреть заставку первого визита. index.html удерживает её не менее 1500 мс плюс 500 мс на закрытие; основной интерфейс оказывается закрыт примерно 2 секунды даже при быстром интернете. Убрать обязательное ожидание или сделать короткую необязательную анимацию.
3. Отложить загрузку скрытых кадров слайдера. loading=lazy не гарантирует отсрочку для изображений, расположенных рядом с viewport, даже при opacity:0. Desktop-прогон загрузил все 12 дополнительных hero-кадров. Скрипт также переводит кадры в eager (строки 683, 732); на mobile началась загрузка скрытого следующего кадра. Использовать data-src и загружать текущий/следующий кадр при необходимости; останавливать подготовку кадров, когда слайдер скрыт.
4. Уменьшить превью дипломов. В desktop-прогоне без прокрутки загрузились credentials-04-cropped.webp (658 КБ) и credentials-05-straight.webp (693 КБ): вместе 1,35 МБ. Подготовить небольшие превью для карточек, оригиналы загружать при открытии.
5. Добавить srcset/sizes для hero и карточек. Hero сейчас 196 КБ, исходная ширина 1122 px при мобильной области 390 px; одинаковый ресурс используется для разных размеров. Подбирать размер с учётом DPR. Портрет уже использует srcset.
6. Настроить явное кеширование статических ресурсов. В проверенных ответах HTML/CSS/JS/hero отсутствовали Cache-Control и Expires; Last-Modified и ETag есть. Для долгого immutable-кеша изображений сначала внедрить версионирование URL, для HTML использовать короткий срок или revalidation.
7. Оптимизировать assets/icons/max.svg: 72,9 КБ для маленькой иконки. Gzip даёт 9,7 КБ; дополнительно проверить возможность упрощения SVG.

Google Fonts подключены блокирующей таблицей стилей с display=swap и preconnect. Их сетевое влияние в браузерные числа не включено. Отдельно проверить локальный хостинг шрифтов и подмножества кириллицы/латиницы.

Размытие большого hero-фона и backdrop-filter шапки — кандидаты для проверки плавности на реальном слабом телефоне; влияние на FPS этим замером не установлено.

## Дополнительная находка

Публичный сервер возвращает X-Robots-Tag: noindex, nofollow, в том числе для главной. Это не проблема скорости, но препятствует индексации; если сайт должен быть открыт поисковикам, проверить серверную конфигурацию.

## Вывод

Время ответа сервера в проверке низкое. Главные подтверждённые резервы — обязательная заставка, отсутствие сжатия CSS/JS и лишняя загрузка изображений. Сначала устранить их, затем повторить production Lighthouse mobile/desktop с рабочими шрифтами и несколькими прогонами. Данных реальных пользователей и INP этот аудит не содержит.
