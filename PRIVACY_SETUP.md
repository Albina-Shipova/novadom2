# Подключение аналитики и окончательное оформление политики

- В `privacy.js` замените `const COUNTER_ID = null` на числовой ID счётчика Яндекс Метрики. До этого аналитика не запускается.
- Включите Вебвизор в настройках счётчика. `privacy.js` загружает Метрику и Вебвизор только после подтверждения записи согласия сервером. Отдельный код счётчика или noscript-пиксель обойдёт этот механизм.
- До публикации окончательной политики подтвердите юридического оператора и добавьте в раздел 1 `privacy.html` и `consent.html` полное ФИО / наименование и адрес. Для обращений указан Russua.anna@ya.ru. Сейчас там только публичные имя студии и контакты; они не подтверждают юридический статус оператора.
- Согласуйте с владельцем реальные сроки хранения аналитики и серверных журналов, меры защиты, условия хостинга и применимые обязанности оператора (включая уведомление Роскомнадзора и локализацию). Текст страницы не заменяет эти действия.
- Шрифты Golos Text и Prata и их лицензии находятся в `assets/fonts/`. Публикуйте каталог вместе с сайтом.
- Журнал использует существующий Django API проекта `crmasama`, как на ramprikosnovenie.ru. При публикации синхронно обновите `asama_crm/consent.py` на сервере. API принимает редакцию `2026-11-25` для `https://tsarevadesign.ru` и хранит события в отдельной SQLite-базе `consent-journal/tsarevadesign.ru.sqlite3` вне веб-каталога.
- Перед подключением счётчика добавьте ежедневную задачу в панели Timeweb и проверьте её запуск. API для домена отвечает, но Timeweb отклонил установку расписания по SSH. Без задачи просроченные записи удаляются при поступлении очередного события. Срок в 180 дней распространяется на журнал согласий. Срок хранения статистики Метрики определяется отдельно. Если журнал включён в резервное копирование, проверьте срок хранения архивов.

```cron
15 4 * * * cd ~/crmasama/public_html && ../venv/bin/python manage.py shell -c 'from asama_crm.consent import prune_expired; print(prune_expired())' >> ~/crmasama/consent-prune.log 2>&1
```

## Перед запуском формы

- В `privacy.html` и `enquiry-consent.html` укажите подтверждённые данные оператора, получателей данных, сроки хранения заявки и записи о согласии, а также контакт для отзыва. Согласие на аналитику оформляется отдельно.
- Подключите серверную отправку заявок на Russua.anna@ya.ru. Сервер должен проверять отдельную, изначально пустую отметку согласия и сохранять заявку вместе с версией согласия и временем его получения. Настройте удаление заявок и записей о согласии по указанным в документах срокам.
- Форма отправляет JSON на `enquiry.php`. PHP передаёт письмо встроенному почтовому сервису Timeweb от `noreply@tsarevadesign.ru` на `Russua.anna@ya.ru`. Проверьте доставку контрольного письма перед включением формы.
- Обработчик включается через `private/enquiry-settings.php` рядом с `public_html`. Файл должен возвращать массив с `consent_version` (редакция опубликованного согласия, совпадает с версией в `script.js`), `retention_days` (утверждённый срок хранения) и `rate_key` (случайный секрет для ограничения частоты). SQLite хранится в этом же закрытом каталоге. Обработчик удаляет просроченные записи при поступлении заявки. Для удаления независимо от трафика настройте ежедневную задачу.
- Включите `enquiryFormEnabled` в `script.js` после проверки отправки и публикации окончательных текстов. Окно помечено `ym-hide-content`. При подключении счётчика отключите запись полей в настройках Вебвизора и проверьте тестовую запись.

Согласие опубликовано отдельной страницей `consent.html`, редакция 2026-11-25. Браузер хранит текущий выбор 180 дней под ключом `nova-dom-privacy-v2`. Новая редакция запрашивает согласие заново. При смене редакции обновляйте текст, версию в `privacy.js` и разрешённую версию в Django API.
